## 评估层与现有资产

| 层级 | 要回答的问题 | 数据与判定 | 当前状态 |
|---|---|---|---|
| 工程回归 | 未知是否保留、该补问是否补问、失败是否被当成功、引用是否丢失 | 17条[问诊/来源控制题](../../evals/consultation-optimization/catalog.json)；程序约束 | 新记录入口可复跑 |
| 检索质量 | 是否找对原文、排序是否合理 | 冻结知识库与人工标注的证据范围 | 待建并核对 |
| 上下文/引用 | 是否保留前提与例外、引用是否支持具体陈述 | 原文范围与完整限定条件；人工核对 | 工程检查已有，完整质量题库待建 |
| 多轮问诊/报告 | 是否漏问、误结束、编造事实或产生不适用建议 | 合成完整脚本；医护标注必要项及报告尺度 | [10条流程冒烟](../../evals/patient-smoke/README.md)已定义，非完整成绩 |
| 运行与恢复 | 延迟、用量、超时、重试、保存与权限 | 实际入口与明确隔离环境、故障注入 | 按每次实际执行记账 |

不同层不混成一个总分。RAG 命中率、工程通过率与诊断准确率不是同一指标。测试资料不得使用未经授权的真实患者记录。

## 题集建设：先做代表样本，再扩大

1. 从用户反馈和已确认的失败建立工程回归案例；保留旧通过案例防止修好一个、弄坏另一个。
2. 选定具有可追溯出处的指南和药物参考，冻结文档版本、文本哈希、索引/切分版本、向量模型与维度。无对应权威资料的题不能要求模型猜答案。
3. 首批建议40～60条RAG题，覆盖精确词、口语/术语改写、跨片段条件、否定/禁忌、儿童成人差异、版本冲突及无答案。每类至少保留代表案例，不只挑容易命中的问题。
4. 每题由原文建立 gold，不由当前检索输出反推答案；开发集可用于调参，封存验收集不能反复用于选择参数。同一原文及改写问题尽量成组划分，避免换措辞就泄漏到验收集。
5. gold 是证据单元，而非固定分块 ID：保存文档版本、章节/页码（存在时）、字符范围与完整原句，允许一个单元由多个片段共同覆盖。切分变了也能评价是否覆盖同一原文。
6. 先用5～10条跑实际检索入口，查看各阶段与原文、校准正确/错误/缺失评分；再扩量。医学支持与适用性标注由专业人员核对；程序自动校验原文坐标，不能替代医学判定。

### RAG 题目字段

`case_id / dataset_version / split / family / query / synthetic_patient_context / expected_action / gold_evidence / forbidden_evidence / required_qualifiers / review_status / reviewer / source_snapshot_id`。

`gold_evidence` 的每个单元包括文档版本、原文定位和完整引句，可标必需证据和替代证据组；无答案题显式 `expected_action=no_evidence`，gold为空。`review_status` 未核对的题不得混进临床准确率。患者条件未知时保持未知，元数据缺失不自动断言不适用。

## 预先定义指标与门禁

| 指标 | 如何计算或判断 | 避免的误读 |
|---|---|---|
| Evidence Recall@K | 被覆盖的必需证据单元数 / 全部必需单元数 | “命中至少一条”另记 Hit@K，不能叫完整Recall |
| 排序 | 按标注相关等级计算nDCG@K，或首个相关证据排名 | 可信度不能替代相关性 |
| 条件完整率 | 找到主体证据且保留全部必需限定条件的题 / 适用题 | 仅找到治疗关键词不算完整 |
| 无答案误接受率 | 无答案题却给出有效证据/成功报告的题 / 无答案题 | 无答案题不用正例Recall评分 |
| 引用支持率 | 被专业核对为原文支持的陈述 / 已核对带引文陈述 | 引用编号存在不等于原文支持 |
| 问诊质量 | 必要项覆盖、重复询问、未知保留、误结束，分别统计 | 题目减少不能单独证明优化 |
| 耗时与成本 | 实际入口P50/P95、成功与失败比例、实际供应商用量 | 失败不从分母消失，null不补0，不重复加推理/缓存子项 |

先固定当前基线再约定数值目标，不预先编造提升百分比。禁止新增“编造来源、错误成功、权限泄漏、丢失必要限定条件”等阻断回归；质量达标之后才比较成本。模型有波动时，同一输入配对重复运行，报告运行次数、逐题差异与波动范围；小样本不宣称统计显著或临床有效。

## 每次优化的固定步骤

| 步骤 | 必须留下的记录 |
|---|---|
| 0 基线 | 当前源码/未提交内容快照、题集、模型/提示词/参数、语料与索引、评分器、完整逐题结果 |
| 1 假设 | 一个具体失败机制、受影响题目、主指标、质量底线、停止条件 |
| 2 修改 | 优化编号、修改文件、主要变量、原因、恢复点；同时变多个变量时说明无法归因 |
| 3 小样本 | 正例、反例和故障用例的输入、输出、判定及真实执行日志 |
| 4 同题对照 | 同数据同评分器运行改后版本；外部搜索冻结响应或另列在线波动，不能偷偷换语料 |
| 5 报告 | 各指标前后值、逐题改善/退步、未评分/异常、耗时/成本缺口、是否允许保留改动 |
| 6 封存 | 数据/代码/配置版本、证据路径；新失败加入下一版题集，保留旧版本，不重写历史成绩 |

优先优化顺序：建立当前真实检索基线 → 独立语义召回 → 原文上下文扩展 → 版本/适用性元数据。每一项独立编号与对照，未实现项不写成绩。

## 优化记录模板

每次在独立运行目录保存一份，使用[记录工具](../../evals/evidence/README.md)生成固定控制层对照。真实RAG与模型按下表补充，不伪装成已支持的运行模式。

| 字段 | 必填内容 |
|---|---|
| 实验编号/日期/状态 | 例如EXP-001；planned / running / improved / no_gain / regressed / incomparable |
| 问题与假设 | 具体失败和预计改善机制 |
| 改动与恢复点 | 文件、参数、主要变量、旧代码/配置位置 |
| 数据与环境 | 题集、语料、索引、模型、提示词、评分器版本和指纹 |
| 主指标与底线 | 运行前定义，不根据结果改标准 |
| 改前/改后证据 | 原始输出、执行日志、阶段候选、逐题判定路径 |
| 改善与退步 | 列具体题目；注明缺失、失败、未评审 |
| 成本与耗时 | 实际值、样本量、来源；缺失写unavailable |
| 结论与局限 | 有效仅限已验证范围；是否保留、下一步 |

## 第一阶段验收与当前证据

1. [量尺测试](../../evals/evidence/test_run.py)拒绝空/缺失/重复/多余结果；原始结果与源码快照指纹不符时拒绝比较。
2. 前后题集、评分器、执行器或环境不同，判不可比较；同版本复跑判无质量收益，不能自动生成“优化成功”。
3. 保留逐题差异，即使总分不变，新增失败仍判退步。
4. 当前源码17条完整基线与同版本复跑，不是语义检索优化。执行证据与命令见[工具说明](../../evals/evidence/README.md)；原始本地材料不随公开克隆分发。

后续需实际文档/索引冻结、RAG gold核对、真实入口小样本和完整评测，才能提交“语义检索/上下文补充有效”的报告。没有这些证据时只报告实现与工程回归状态。
