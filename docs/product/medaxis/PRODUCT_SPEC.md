# MedAxis 行为与验收规格

> Status: REVIEW · 2026-10-09 · 只维护跨模块验收；专项字段及详细状态见原规格

## 如何使用

本文件定义“要怎样才算正确”，不声称场景已经执行。下面的 `A-*` 是验收索引；证据要求对应 [能力事实表](DEVELOPMENT_READINESS.md)，执行方法沿用现有测试/评测入口。默认使用合成数据，真实写入及专业签署需另行授权。

## 核心验收

### MX-01

**A-01 身份与模式：** 普通患者登录后看到本人数据；访客知道过期及额度限制；开启面试模式时，仅专用 active 患者可调用模型。额度耗尽停止新模型请求但保留浏览。普通访客按提交计数、失败可按服务规则返还；面试模式按实际 provider HTTP 尝试持久扣减，重试计入、失败不退还、上限配置 1–20。验证重新启动/并发请求不自动补充；这不是 token 上限。当前开启状态 UNKNOWN。

### MX-02

**A-02 补问：** 已知信息可复用，未知允许保留未知；修正前文后后续采集依据新陈述；SSE 中断不伪装完成，已显示内容及下一步可辨认。题量节省与关键缺口分别评估，不能以少问为唯一成功。

### MX-03

**A-03 证据门禁：** 有可核验来源且形成有效引用才发布辅助报告；检索超时、零来源、引用失效显示可理解失败。来源相关性、要点覆盖、原文支持和患者适用性是四种不同判断；任一未验证状态不能显示已专业审核。知识库为空/embedding 不可用/重排失败均单列场景。

### MX-04

**A-04 保存：** 同一来源会话重复保存返回同一病例语义；未保存成功不能显示已归档。用户 A 不能读写 B 的病例；迟到响应不能串入当前病例。生成失败与保存失败分别报告；清浏览器后只承诺恢复服务端已保存资料。

### MX-05

**A-05 就医准备：** 修改草稿、成功保存、复制使用的版本分开；冲突保留输入并要求重新核对。来源修订后显示过期状态并禁用旧摘要复制；更新成功后再复制。切换阶段可保留当前会话草稿，刷新/离开会丢未保存输入，需提前说明。详见 [就医准备](../VISIT_PREPARATION_SPEC.md)。

### MX-06

**A-06 诊后自报：** 在正确病例保存反馈，带 revision，冲突不覆盖较新版本，历史可追溯。本人自报“医生说了什么”不成为平台医生签署；保存不自动创建用药任务。

### MX-07

**A-07 归档：** 本人上传有序页组，独立报告可不关联病例；相同字节及顺序按本人去重，用户明确选择复用或新副本。复用不覆盖历史。未保存上传刷新丢失，保存失败可重试且不重复创建。报告删除与恢复、病例关联对删除状态的响应单列验证。已有 10MiB/5文件/20页/批次5份为专项中的实现常量与假设，不把它们提升为新获批需求。

### MX-08

**A-08 外发同意：** 新报告先本地取字；患者看到脱敏文字、接收模型和来源版本，明确同意本次发送后才外发。预览后文字/原件/接收方变化拒绝旧同意；失败不自动重发、不静默切换供应商。人工编辑文字仍需重新核对同意。旧 `/documents/upload` 的视觉/文件外发是不同入口，不能套用“所有原件不外发”表述。

### MX-09

**A-09 核对与引用：** AI 候选不覆盖手动草稿；确认生成不可变核对版本。病例固定引用来源与核对版本；源或核对改变显示待重新核对，不能悄悄改成新结论。本人核对不得显示医生审核。详情、关联、原件和回收操作都应拒绝跨用户访问。

### MX-10

**A-10 档案/测量：** 未填、未知、明确无、已有记录分别显示；删掉最后一条不能自动变“明确无”。修改带修订号；409/428保留草稿。测量重复 request_id 同内容返回既有结果、不同内容拒绝。详见 [档案规格](../HEALTH_PROFILE_SPEC.md)。

### MX-11

**A-11 手动计划：** 待确认计划只有确认后生效；暂停/终止停止未来事件，已发送记录仍存在。任务重复完成不改变首次记录；并发按版本冲突处理。日程按既有 UTC+8 约定核对；任务数、日期和生命周期沿用 [随访规格](../FOLLOWUP_PLAN_SPEC.md)。

### MX-12

**A-12 候选转任务：** 从已保存诊后原话取候选，逐次同意，默认不选；患者逐项确认并补足时间才生效。缺失剂量/药名不能由 AI 补成处方；来源变化取消尚未发送的关联计划与事件，已发送无法追回。详见 [诊后 AI](../POST_VISIT_AI_ACTIONS_SPEC.md)。

### MX-13

**A-13 提醒：** pending/sent/acknowledged 等送达状态不等于任务完成或医学效果；只有 sent 可确认，重复确认幂等。邮件只发通用提示，SMTP 失败不能写送达成功；发生发送后落库失败时记录可能重复的边界。不承诺即时监护或 exactly-once。

### MX-14

**A-14 定向咨询：** 患者选择可用认证医生、资料快照并同意；同病例只能一个活动咨询。快照变化重新核对；重复提交幂等。医生接受/婉拒、患者补充、医生回复与结束有历史记录。回复写入原咨询，通知已读不改变咨询状态。

### MX-15

**A-15 授权撤销：** 患者取消、咨询结束、医生认证撤销或账号失效后停止继续共享；读取和发布都重新验证。旧 `/doctor/*` 和 `/medical-cases/*` 也必须满足已裁决的对象范围，不能仅凭前端角色守卫。已下载/外发的材料不能远程追回。现有医生 API 的患者全量会话查询与认证差距，见 [实现差距](DEVELOPMENT_READINESS.md)。

### MX-16

**A-16 运营结果：** 非管理员不能调用管理 API；最后 active admin 和本人误踢受保护。医生审核批准和邮件送达分别显示，邮件失败不能显示“已发送”。明确数据库删除与停用区别；现有 kick 为实际删除，不能宣称软删除可恢复。关键动作审计覆盖须逐项证明。

### MX-17

**A-17 服务配置：** 知识审核、模型配置、通知及邮件操作在加载/失败/取消时保留明确结果；模型健康检查不成为患者数据外发默认授权。记录变更前后版本及操作者；未验证的管理表单不写“已完成联调”。

### MX-18

**A-18 机构/研究：** 咨询同意不得转为病例库或研究同意；只有同机构认证医生、另行患者同意且审核后的材料进入目标病例库。导出清单、字段、用途、版本、有效期和撤销后的下载副本处理需裁决；实现前不显示已支持。

### MX-19

**A-19 数据退出：** 用户能分辨取消当前操作、回收报告、恢复、永久清理与停止外发；不把退出登录解释为服务器删除。保留时长、备份覆盖、第三方保留、研究副本生命周期缺失时列 UNKNOWN。没有完备证据，不承诺绝对匿名或全部可撤回。

## 动作—状态耦合

| 动作 | 草稿 | 服务端保存/历史 | 已生效自动化 | 分享/外发影响 | 恢复 |
|---|---|---|---|---|---|
| 保存就医准备 | 成功后以新版本为准；失败保留 | revision 前进 | 无自动任务 | 只复制已保存新版本 | 冲突先对照；不覆盖较新记录 |
| 更改报告原件/文字 | 核对输入需重新对照 | 新来源版本，旧核对留历史 | 不由报告候选自动生效 | 旧预览/同意失效，引用显示变化 | 原件仍可人工整理 |
| 更改诊后原话 | 保留未提交输入 | 自报历史追加 | 关联待发送计划/事件失效 | 旧候选不再可确认 | 新一轮预览与同意；已发不追回 |
| 暂停/终止计划 | 不伪装完成任务 | 状态/版本改变 | 取消未来排程 | 已发提示保留 | 恢复 active 按专项规则；不自动补发所有历史 |
| 取消咨询/医生失效 | 未发送留言有退出提示 | 咨询进入终态，历史保留 | 不自动转接新医生 | 停止共享；已下载不能撤回 | 患者重新选医生并授权 |

## 产品承诺的证明要求

以下覆盖所有建议 P0 承诺；相同证据维度合并展示，不能跳过其中编号。所有运行要求均是后续待执行，不是本轮通过声明。

| 承诺 / ID | 不变量与失败模式 | 验收 | 所需证据 / 真人边界 | 当前允许表述 |
|---|---|---|---|---|
| 正确身份与限制 MX-01 | 越权/过期/并发不得绕过额度 | A-01、A-15 | 独立身份与并发测试、目标配置；真人决定演示账号及预算 | 有身份/额度控制代码，当前配置未验证 |
| 不凭空完成报告 MX-02/03 | 未知变无、无来源发布、引用虚构 | A-02/03 | 固定失败集、真实入口、专业原文审核；AI 不代签专业结论 | 有补问与来源门禁，语义支持能力未完整验证 |
| 保存与恢复可信 MX-04/05/06 | 串病例、假保存、旧摘要复制、冲突覆盖 | A-04/05/06 | 双账号、双页并发、清缓存重登；仅合成写入 | 有持久与版本控制代码及部分历史样例 |
| 新报告用途可控 MX-07/08/09 | 原件误外发、旧同意复用、候选冒充本人核对 | A-07/08/09 | 本地 OCR、外发拦截、组合恢复、当前部署；真人批准材料/接收方 | 有分层处理代码，完整部署组合验收未完成 |
| 分享与退出 MX-15/19 | 未认证访问、授权撤销无效、删除不可恢复却称可恢复 | A-15/19 | 跨入口权限/撤销/清理证据；真人裁决保留和下载边界 | 新咨询有约束，旧医生入口与保留政策存在关键差距 |

## 最小验证顺序

先无副作用静态/单元检查，再合成数据隔离集成，之后目标环境恢复与权限验证，再做真人可用性及专业核对。成本、外发、真实患者或生产操作不能从本文件推导为执行授权。已确认 bad case 回流到现有评测记录，不在这里复制题库。
