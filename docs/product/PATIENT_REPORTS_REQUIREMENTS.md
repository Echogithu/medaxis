## 2. 首期功能建议

下面保留需求分期建议；当前实现目标覆盖完整闭环，具体实施顺序见任务计划。归档验证切片为：注册患者独立上传一份图片/PDF → 保存名称/类别/日期 → 列表查到 → 详情对照和下载同一原件 → 明确移除及本人权限隔离。上传/响应失败能重试并恢复，不依赖问诊和外部模型。

AI整理、人工结构化核对及病例关联是后续扩展切片，仍保留在本需求稿；多文件批次、多页合并、内容去重、多病例引用、回收站历史恢复是增强候选。每项下表优先级都是待整稿裁决的建议，实施计划不能直接把所有P0相加成首轮任务。

| R1 | 独立「检查报告」导航和患者级列表，不要求先建立问诊会话/病例；刷新、退出登录后重新登录、换设备仍能读取已归档资料 | P0 |

R9当前实现边界：按同一患者、有序文件的字节hash匹配，文件重命名不改变重复判断；重排页序属于另一来源。默认先提示，选择复用只读取已有报告，本页新名称/日期/备注不覆盖它；另存创建独立报告。显示最近5份本人候选并说明截断，不做语义相似匹配或自动合并。重试返回同一报告及当前状态，不冻结旧响应快照；报告删除后的提交墓碑拒绝旧编号重新创建，管理删除入口已接入，最终验收与清理策略仍待确认。

当前实现支持JPEG、PNG、WEBP、PDF，每文件10MiB、每份最多5文件/合计20页；批次页面最多5份、逐份提交，因此一份失败不撤销其他已归档项。这些有界默认值仍属ASSUMPTION，可依据目标环境及实际使用调整。真实签名、声明类型、解码、页数已校验，空/损坏/伪装/加密/超限会拒绝；支持手机文件选取，自动裁切、矫正、HEIC转换待后续。

首期建议仅管理本人报告；家属/被照护人需要独立归属与授权设计。识别到姓名不一致时提示确认归属，不因登录账号归属就宣称报告一定属于本人，不自动纳入本人分析。

首期不包含：影像/DICOM诊断、根据异常开药/调药、自动修改健康档案、自动创建随访/提醒、默认向医生/机构/科研共享、访客独立云归档。关联病例只建立患者侧引用，不推定医生可见；新增报告对既有咨询授权的覆盖范围明确后，才开放对应医生访问。

## 3. 页面需求（按截图调整）

**列表页**：检查报告标题及简短用途、上传按钮；真实数据的已归档份数、待本人核对份数、最近检查日期；全部/检验/影像/其他/待核对分类，搜索，分页报告卡片。

- 卡片展示名称、检查日期（含年份，未知明确显示）、医院、类别、归档/整理/核对状态、更新时间和查看入口。
- 异常摘要写「原报告标注偏高/偏低/阳性」等来源语义。原件未标、参考范围缺失、文字识别不清时显示未知/需核对，不能据模型默认值写正常。
- 全部AI结果都待本人核对，不仅低置信度结果；本人已核对不是医生审核、临床有效或已诊断。将截图「需人工复核」优先命名为「待本人核对」，需要专业意见另行提示。
- 右侧进度区展示当前批次/所选报告的真实进度；没有任务时收起或显示简短操作说明。不能用示例步骤冒充任务状态。
- 正式页面移除示例报告和合成计数；演示模式另行明确标记且不混入真实统计。

**上传流程**：选择/拍摄 → 校验 → 将同一报告多页归为一份并确认页序 → 填写报告信息 → 保存原件。可先归档后补信息；分组建议默认一文件一份，用户明确合并多张同一报告图片。不同报告不能自动合并，报告“份数”不等于页数或文件数。

**详情页**：桌面原件/结果并列；手机切换查看。原件支持缩放、翻页及安全下载。整理结果支持编辑、保存草稿、确认核对、查看修改历史；清楚展示来源和最近核对时间。PDF内含多份报告时提醒拆分，首期不承诺自动拆分识别。

**隐私步骤**：本地文字提取 → 患者检查/修改脱敏预览 → 展示本次接收方及将发送的完整文字 → 明确同意 → 整理。可随时在发送前退出；缺少文字时人工录入或仅保留原件。

## 4. 术语、数据和来源

| 术语 | 含义 |
|---|---|
| 检查报告 | 本人一项检查的资料单元，可由一个PDF或多张有序图片组成；归属患者，可关联零个或多个本人的病例 |
| 原件 | 患者上传的文件，保存后不被人工修改或AI结果覆盖；更换原件形成新的来源版本 |
| 本地提取文字 | 从原件本地取得的待核对文字，不代表内容已经正确或可以默认外发 |
| AI整理候选 | 基于本次同意文字提取的结果，尚未成为本人已核对内容 |
| 人工填写/修正 | 患者录入内容，保存不等于核对完成；与机器原始提取区分，保留历史 |
| 本人已核对 | 患者明确确认已对照原件的某一版本；不等同于医生审核 |
| 报告关联 | 指向同一报告版本的病例引用；不复制成互相矛盾的报告，也不自动授予新角色访问权 |

报告信息：名称、类别（检验/影像报告文字/其他）、机构、检查日期与报告日期、备注、文件列表/页序、来源渠道、归属确认、上传/更新时间、版本、关联病例、核对人/时间。

检验指标：原始项目名、原始结果（数字/定性文字）、单位、原报告参考范围、原报告异常标记、来源页/文字、来源类型、患者修改内容、核对状态。缺失、未识别、原报告明确无/正常分别保留；不自动填“正常”、补单位、补参考范围或用其他医院范围替代。LOINC等标准编码非首期必填。

影像报告文字：检查类型/部位、报告日期、医生书写的检查所见和结论、来源页/文字。没有检验指标的有效影像文字报告不能因指标数组为空被判为解析失败。

原件、提取文字、AI候选、人工修正、核对版本分别可追溯。已核对后更换原件/页序/关键文字，旧核对不继承，新版本需重新整理或核对；只改显示标题/备注不默认重新调用模型。

## 5. 状态、失败与恢复

归档状态、整理状态、核对状态分开，禁止用单一「已整理」同时表达三者。

| 状态维度 | 状态和可用操作 |
|---|---|
| 归档 | 未上传/上传中/已归档/上传失败/回收站；成功后即使识字失败仍可查看原件 |
| 整理 | 未整理/本地提取中/待同意/AI整理中/待本人核对/整理失败/人工填写；未同意绝不进AI整理 |
| 核对 | 未核对/草稿已保存/本人已核对/来源变化需重新核对；修改后的草稿不覆盖上一核对版本 |

用户可辨认每份文件实际进度和阶段；刷新后恢复服务端任务状态。前端等待超时不能伪造后端任务失败，仍可返回稍后查看。上传成功但响应丢失、AI成功但响应丢失的重试要能取回同一任务/结果。

失败分清文件问题、无可识别文字、外发未同意、模型不可用/超时、结构不可信、保存冲突。错误不回显整份报告、凭证或模型原始异常。识字失败引导补清晰原件/人工录入；AI失败保留原件/文字及人工草稿，不生成示例指标。

并发修改时提示版本冲突，保留本页草稿并提供对照/重新加载；重新加载会丢弃本页未保存内容时须明示。重解析先生成新候选，用户核对前不覆盖旧已核对结果。

| 用户动作 | 原件/归档 | 草稿/核对 | 关联与自动化 |
|---|---|---|---|
| 保存原件 | 创建本人独立资料 | 未核对 | 不调用外部模型，不自动写档案/安排 |
| 同意AI整理 | 保留 | 新候选待核对 | 同意绑定本次文字、来源版本、接收方；变化须重新同意 |
| 保存修改草稿 | 保留 | 草稿版本持久化 | 不自动标本人已核对 |
| 确认已对照原件 | 保留 | 对当前版本记录确认 | 允许显式选择用于病例；仍不创建安排 |
| 替换原件/重解析 | 保留旧版本 | 新版本重新核对 | 旧引用标来源过期，不静默用于新的AI分析 |
| 移入回收站 | 移除活动列表，可恢复 | 保留历史 | 撤下活动引用、取消未发送候选；已发送内容不可召回 |
| 恢复 | 回到活动列表 | 保留合法历史，不凭恢复自动确认 | 关联可由患者重新选择，不自动重新授权/触发模型 |

本期报告不直接生成随访/用药任务，删除报告不应擅自停止已确认的治疗/安排。若未来支持从报告直接生成安排，须补独立确认、来源失效和撤销规格后再实现。

## 6. 隐私与权限（已确认隐私方式）

- **OWNER_DECISION**：脱敏文字预览＋逐次同意。患者原件保存到平台与发送到外部模型是两件不同的事，界面解释清楚。
- **处理位置建议（ASSUMPTION）**：本文「本地提取」指患者设备或平台自管环境中的文字提取，禁止将原件交给外部OCR/文件解析/模型供应商。首期推荐先将原件归档到MedAxis平台，再在平台自管后端本地识字；执行位置及依赖由可行性验证后裁决。此推荐不是原件只保存在患者设备的承诺，UI须明确原件会上传保存到平台。
- 原件仅在本人归档/查看和本地取字中使用，不经现有外发原件路径自动解析；本地OCR/文字提取不可用时，不回退到云端识字。文档内容是资料，不能指示系统绕过同意或调用工具。
- 外发不含原始文件、图片、附件链接、文件名、患者/病例ID、医院账户标识、完整档案；只含本次最少必要的脱敏文字。姓名、电话、证件、住址、报告条码编号等先遮蔽，但不宣称规则完全去标识。
- 首次同意、重新整理、文字/来源版本变化或接收方变化都重新检查本次同意；同意不默认勾选。不用「同意使用AI」总开关覆盖此要求。
- 取消未发送任务阻止新外发；已发给模型的内容无法召回，不能承诺平台删除等于服务方即时删除。同意摘要和来源版本可追溯，日志避免记录报告全文、身份或下载令牌。
- 上传、列表、原件、下载、提取文字、修正、确认、关联、删除及恢复都在服务端逐对象检查本人权限。不能因知道文件ID/URL就读取其他用户原件；原件不得使用长期公开链接。
- AI待核对结果默认不进入新的诊断/健康画像输入；本人已核对且明确选择关联后，仍需按对应AI流程同意外发。病例关联不会自动授权医生读取新资料，已存在授权对新增报告的覆盖范围需按医生协作规格确认。
- 首期不引入报告邮件附件/短信/锁屏内容。需要通知时只显示「有资料待核对」并要求登录查看。
