## 原因与修复

| 问题 | 修复前原因 | 当前行为 |
|---|---|---|
| 来源及说明消失 | 报告只保留正文中出现编号的来源，模型漏编号就把全部资料隐藏 | 保留全部实际选中的来源、标题、类型、原文及相关性说明；区分正文引用和检索参考资料。漏编号时最多补绑定一次，仅加入合法编号，不改医学正文 |
| 出现 `adv_stool_pattern` 等字段 | 内部缺口标识直接进入患者展示；不同原话一律判冲突 | 已知字段转中文，未知技术标识隐藏；互补疾病信息不因文字不同就判矛盾，真实否认/肯定或同一回答修改等仍需核对 |
| 必要信息未问就结束 | 轮数预算/停滞把模型产生的必要题清空；空题直接进入总结 | 建议轮次不能截断必要题。已列出的未问必要缺口尝试恢复生成一次，仍无有效问题则显式失败；已回答“不清楚”的原项不反复问，继续其他必要项 |

历史报告的引用列表已经为空时，前端历史恢复及病例恢复 API 从同一会话保存的检索记录读取原来源，保留原编号及原文，不写回数据库。没有原记录则无法恢复，不能编造来源；也不能借用报告之后的追问来源。

主要修改位置：`backend/app/services/orchestrator.py`（缺口与停止）、`backend/app/models/interview.py`（信息状态）、`backend/app/services/knowledge_citations.py` 与 `agents.py`（来源保存和编号绑定）、`backend/app/api/v1/patient.py`（授权范围内的历史恢复）、`frontend/src/state/reportCitations.ts` 与 `chatHistory.ts`（本地历史恢复）、`PatientReportBody.tsx`、`ReportCitationCard.tsx`、`patientText.ts`（患者展示）。设置说明及兼容可选字段同步更新；无数据库迁移或新依赖。

## 如何验收

前置条件：使用加载当前后端源码和前端构建的隔离测试环境、合成患者资料。当前运行服务没有自动重启或部署，旧服务不能作为本次修复的验收对象。

1. **必要缺口继续问**：输入腹泻两天、程度轻，尚未提供大便性状及相关暴露信息。每轮设 1 题，建议轮数设 1。超过建议轮数，模型判断仍必要的未问项必须继续询问，不能只列“信息缺失”就结束。某项回答“不清楚”后，保留未知，继续其他必要项；不反复换措辞问原项。具体顺序由模型判断，不能把本次探测的措辞当成唯一正确答案。
2. **信息展示可读**：加入“轻度焦虑；甲亢严重程度不清楚”的合成病史。不能仅因这是两种不同描述就显示前后冲突；总结中不出现 `adv_stool_pattern`、`adv_epidemic` 等内部字段。真正未确认的信息使用中文，患者已明确未知的项不冒充已确认。
3. **来源可追溯**：新报告展开“参考资料与说明”，能看实际选中来源、相关性说明及原文，正文编号能打开同编号卡片，未引用资料仍可阅读。重新打开原来来源列表为空的历史报告：若保存过原检索记录，应恢复原来源/编号；没有记录应如实说明缺少原数据，不能随意填来源。

记录每轮题目/答案、停止时未问项、来源编号和截图。验收完整医学采集、来源适用性及漏问率仍需要专业评审；机械测试不能替代这项判断。

## 自审、恢复与边界

本次重点攻击的失败点：预算吞掉必要题、未知同义题重复、互补病史误判、补绑定伪造原文、历史恢复越权或拿错后续资料；均有对应回归。引用补绑定限制原有医学字段、实际来源编号和完整原文，失败时仍保留参考资料。病例恢复保留所有权检查，外人来源会话返回 404。

剩余边界：缺少已保存原检索记录的历史报告无法还原；原文匹配不证明医学适用性，改写陈述仍可能需要核对；必要问题的识别依赖模型，单次探测不能证明临床完整性。额外绑定或恢复生成可能增加一次调用，本次不宣称成本下降。

恢复时先对照局部 baseline 和当前差异，只撤销本次修改的片段，保留其他任务。历史恢复没有数据写回，无数据迁移需要撤销；不得全仓 reset 或直接覆盖全部文件。未 commit/push，未部署，未修改运行中的数据库设置。
