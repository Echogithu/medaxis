# 就医准备：患者行动页

日期：2026-09-30。来源：用户同意“收拢信息层级、补通用科室建议、后续再考虑医院接入”，并要求开始调整。本次授权覆盖该增量；不撤销旧 PRD 的医生复核目标。

## 默认行为

问诊记录详情顶部提供横向三阶段导航：本次问诊总结 → 准备去就诊 → 记录就诊结果。编号表达任务顺序，当前阶段高亮；不表示医生审核、已经就诊或任务已完成。允许直接切换；长内容滚动时导航保持可见，手机保留三个明确入口。

所选阶段同步至 URL 的 `stage=summary|preparation|visit`，支持刷新和浏览器后退/前进。切换阶段只隐藏原内容，保留两份表单输入；换病例回到总结并继续按病例隔离。总结底部提供下一步入口，准备页提供就诊后记录入口。无总结时说明不能生成准备包，实际就诊结果仍可记录。打印继续呈现问诊总结，隐藏阶段导航与编辑表单。

点击“准备去就诊”后，生成或读取同病例准备包，呈现三个任务：

1. **下一步建议**：有限的通用科室咨询参考与短理由；风险或信息不足时说明可执行的咨询路径。参考依据、日期、适用范围和常见科室按需展开。
2. **出发前准备**：本病例已有资料、当前用药核对、想问医生的问题；不生成新检查或停药指令。
3. **给医生看的摘要**：患者当前陈述、未知、待核对的前后回答、材料和问题。默认节选，完整摘要可展开；逐项确认和更正通过“核对或修改病情”进入。AI 分析、来源和历史在独立详情中。

摘要复制的是已保存的数据。有修改时先保存；更正需要刷新建议时自动生成新包。保存或更新失败不复制；源资料或规则变化导致旧包过期，更新前禁用复制。原始记录与先前更正继续保留，患者核对不表示医生确认。

当前浏览会话内，切换病例保留未保存草稿；返回后先读取本人病例，版本一致才恢复。版本变化时保留旧草稿和清单供核对，不自动覆盖新版本。刷新或离开页面会提示未保存内容，但草稿不写入浏览器磁盘，跨刷新/重登恢复依赖显式保存。重复更正写回原事实；已选咨询主题可改为“其他、多个问题或不确定”撤回专科方向。

## 科室参考的证据和限制

依据是公开院方导诊资料，而不是医院导入表或 AI 生成的疑似诊断。规则只在患者主诉有有限明确匹配时输出咨询方向；多方向时可让患者选择本次咨询主题。未匹配时说明医院导诊/全科咨询路径。

当前参考覆盖呼吸、消化、皮肤、眼、耳鼻喉、口腔、骨科、泌尿、妇产及全科方向。名称、主题、有限词项、来源日期由 `backend/app/services/department_guidance.py` 单处维护，前端读取准备包，不另维护科室表。

- [中山大学附属第六医院：常见疾病导诊指引](https://www.sysu6h.cn/guide/outpatient/502)（发布 2017-02-09）：支持有限的科室与问题方向关联，不能把跨科症状当成互斥规则。
- [北京大学医院：口腔中心就诊说明](https://hospital.pku.edu.cn/info/1013/1232.htm)（发布 2018-09-05）：支持牙痛、牙齿松动等口腔咨询方向，不映射具体挂号门诊。
- [阳春市人民医院：全科医学科](https://www.ycph.com.cn/Category_327/Index.aspx)：支持无法明确专科时咨询全科；不能推定所有医院设有全科门诊。

来源于 2026-09-30 核对。院方介绍不等于本项目规则已获专业临床审核。使用保守的有限匹配；未识别不表示不存在风险，也不表示病情轻。否认、含糊、历史或他人描述不作肯定匹配；儿童、孕期和前后冲突转为人工确认。

已有报告紧急标记优先于科室参考。报告的危险信号可能是条件性提示，系统不自行断言患者已经出现这些信号；非空提示或有限风险词项会保守转为先确认紧急程度。没有紧急标记也不能据此宣称患者适合普通门诊。该策略可能过度降级，需专业人员评审后再扩大自动推荐范围。

具体医院接诊范围、院区、门诊名称和预约属于后续独立能力；本次没有接入。原 FR-11 的完整专业推荐承诺仍不能标为完成。

## 验证边界

2026-10-01 增加原话语境提示：主体、时间、否定、确定性与字符位置保留在准备包；病情核对与复制摘要使用同一提示。规则仅作辅助核对，不改已有患者断言或科室匹配。语境策略版本参与 fingerprint，旧包重新生成后才复制。集成与验收以 [OpenMed 借鉴功能与验收](./OPENMED_BORROWING_ACCEPTANCE.md) 为准。

自动化应覆盖：来源可追溯、否认/未知/冲突/风险处理、AI 诊断不能替代患者事实、旧规则包更新、保存与复制一致、失败保留输入、手机和病例切换。

本次自动化与审查结果见本地任务目录 `.ai/tasks/2026-09-30-visit-preparation/`。浏览器 API 为合成替身，使用真实准备包 builder；数据库回归在独立 `medaxis_test_` 数据库运行。二者都不证明真实模型、临床适用性、患者可用性或已部署到当前运行服务。

专业审核、真实模型主线和患者理解测试仍需补充；手动检查见 `.claude/manual-test-visit-preparation.md`。
