## 1. 产品定位与四层边界

**帮助患者把分散的主诉和问诊信息整理为可核对、可携带、可恢复的就医资料，并把诊后自报反馈保存在同一病例中。** AI 辅助整理信息，患者确认本人陈述；平台当前不提供医生签署的诊断结论。

| Future Target | 有审核依据的科室建议、真实模型可用性、医生复核与后续随访 | 既有需求方向；不代表已交付 |

## 2. 问题与证据

现阶段为 `HYPOTHESIS_MODE`：有用户提出的问题和代码实现，没有足够的用户研究或真实使用数据证明需求强度。

| 问题假设 | 当前替代方式（待访谈验证） | 本产品希望改变的行为 | 已有/缺失证据 |
|---|---|---|---|
| 主诉、时间线和资料分散，患者容易漏讲 | 临时回忆、聊天记录、手机相册 | 就医前核对一份有来源、未知项明确的摘要 | 原 PRD 记录用户问题；无访谈样本与遗漏率基线 |
| 整理后的信息难以再次找到 | 手工笔记和本地聊天历史 | 清缓存重登后仍找回同一病例资料 | 有合成演示恢复记录；无真实用户可用性数据 |
| 诊前资料和诊后反馈割裂 | 单独记医嘱或再次发起聊天 | 在同病例记录患者自报就诊信息 | 有持久化实现和历史测试；无连续使用证据 |
| AI 表述容易被误认为确定结论 | 用户自行辨别生成文本 | 看清原始陈述、AI 整理和患者自报的来源 | 有标签/未知项/版本设计；用户是否理解待验证 |

反证：用户可能更习惯直接给医生看原始材料；问答过长可能增加负担；医生未必认可摘要格式；中性科室目录可能没有独立价值。因此首先验证“资料整理与恢复是否有用”，不要用模块数量替代需求证据。

当前选择这一方向的理由是已有可复用的患者侧实现和隔离演示，补齐证据成本较低；并无市场时机或商业化成立的结论。

## 3. 目标用户、目标与非目标

首轮验证对象建议为愿意使用合成案例参与可用性测试的成年人；任务是描述问题、核对摘要、找回资料和记录反馈。该人群为 `ASSUMPTION`，不是已确认的真实患者群体。医生可作为摘要评审者，暂不要求注册本平台。

目标：证明一条可理解、可恢复、来源清楚的患者信息整理流程；为工程师岗位提供真实模型与系统行为证据，为产品经理岗位提供需求取舍与迭代证据。

非目标：自动确诊/处方、个性化分诊已成熟、自动随访监护、预约/HIS、医生签署、完整跨设备聊天同步、GraphRAG/MCP/移动端。已有外围功能保留，不默认纳入本轮作品验收。

## 4. 核心流程和领域规则

1. 注册患者描述合成主诉，完成至少一次补问；信息未知时允许保留未知。
2. 获取结构化辅助报告，明确生成失败与保存失败；只有保存成功才进入对应病例。
3. 进入同病例就医准备：先显示已有风险提示，再核对摘要、待补充信息与待问问题。
4. 预览并复制摘要，保留来源、版本与患者核对状态。科室目录只用于演示浏览；不得显示为个性化推荐。
5. 在同病例填写患者自报的就诊反馈，保存后可再次读取。
6. 清除浏览器状态并重新登录，从病例列表恢复报告、准备和反馈。

领域约束：会话是信息采集过程；病例是本次问题的持久归属单元；准备包是带来源版本的整理结果；诊后反馈是患者自报。患者确认不改变 AI 输出的医疗效力，自报就诊不等于医生签署。

| 动作 | 状态影响 | 失败/退出要求 |
|---|---|---|
| 完成问诊 | 报告生成与病例保存分别判断 | 保存失败不显示已保存；已有报告保持可见 |
| 切换病例 | 当前病例、加载态、准备及反馈一起切换 | B 失败不得保留 A 的操作区域；迟到响应不得覆盖当前选择 |
| 核对/修订准备 | 编辑草稿 → 成功保存的修订；保留来源关系 | 冲突提示重读，不覆盖较新内容；失败保留输入 |
| 修订来源 | 新旧来源与准备版本应可辨别 | 不让旧摘要伪装为最新；具体失效行为按场景验收 |
| 保存诊后反馈 | 草稿 → 服务端自报记录 | 失败不得显示成功；不得自动生成用药任务 |
| 离开与恢复 | 未保存草稿和已保存记录分开 | 用户可退出；重登恢复承诺只覆盖已保存数据 |

## 7. 成功指标与验证设计

当前下列业务/质量指标基线均为 `UNKNOWN`，不写“效率提高 X%”。目标先定义为形成可重复基线；数值阈值在基线取得后、迭代前冻结，不能看完结果倒改标准。

| 指标 | 口径 | 基线取得方法 |
|---|---|---|
| 流程完成率 | 到达反馈保存且能重登恢复的会话 / 合法启动测试会话；逐阶段记失败 | 固定案例、固定环境、重复运行；替身与真实模型分组 |
| 主诉完整性 | 场景要求的信息中正确记录的项 / 场景要求项；未知与错误补全单列 | 人工标注合成样例，比较原始聊天和生成摘要 |
| 摘要核对耗时 | 从开始看资料到完成指定核对任务的时间 | 同组案例，交替先看原始材料或摘要，减少顺序偏差 |
| 来源忠实性 | 抽样陈述被其关联来源支持的比例；无来源陈述单列 | 标注事实—原文对应；仅 URL 存在不算支持 |
| 恢复与隔离 | 已保存记录恢复数 / 待恢复数；越权拒绝数 / 预设越权用例数 | 重登/重启/身份变化分开统计，不用单个成功案例推断总体 |
| 模型体验与成本 | 首个有效反馈、完整报告耗时的分布；失败率；完整会话 token/费用 | 按模型、流程阶段、样本数和日期记录；不把占位 SSE 当有效反馈 |
| 可用性 | 无引导完成指定任务人数 / 参与人数；误解 AI/自报标签的次数 | 小样本任务观察与访谈，保留失败和反对意见，不推断市场规模 |
