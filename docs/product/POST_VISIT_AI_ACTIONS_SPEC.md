# 诊后 AI 随访与用药提醒

范围：患者保存本人就诊结果后，选择脱敏预览并逐次同意，由当前配置模型提取已有安排。患者核对、选择事项并补齐日期/时刻后创建有效随访及提醒。该确认表示患者核对，不表示医生已确认。

## 患者流程

1. 问诊记录 → 记录就诊结果 → 保存。
2. 点击「预览脱敏文本并整理」，检查脱敏文字、接收模型及主机；发现残留身份信息时取消并修改记录。
3. 本次明确勾选同意后才调用模型。拒绝/取消不会调用；后续重新整理需要再次同意。
4. 候选保留原文依据，默认均不选中；来源仍是患者自述。缺少原文剂量不能创建用药提醒；日期/周期/时刻由患者对照医嘱补齐，系统不猜测。
5. 确认前没有有效计划和提醒事件。确认后随访写入计划，用药按每日时刻创建独立提醒；日期采用北京时间 UTC+8。
6. 随访页、提醒页展示站内待确认入口（最多最近50份）。默认仅站内；患者可选邮件提示，邮件只有「有待查看提醒」等通用内容。
7. 重复确认同一请求返回同一结果；修改确认内容返回冲突。停用本次安排，或修改诊后记录，将取消进行中/暂停的关联计划及尚未发送的提醒。已完成计划和已发送历史保留。

## 隐私与行为边界

- 模型只接收就诊情况、复查事项及就诊日期；不发送科室、病历/患者标识、原始附件、修改历史或健康档案。
- 既有脱敏规则和当前账号已知姓名、电话、邮箱先行遮蔽。规则不能保证自由文本完全去标识，所以逐次预览是必要步骤；健康文本仍交给所展示模型处理，并非本地处理承诺。
- 同意绑定来源ID、修订、脱敏文本、模型和路由摘要；生成请求重新核对，单次请求固定所同意的模型路由。记录/模型变化要求重新预览。
- AI只提取，不能开药、改剂量、诊断或新增原文没有的事项。输出必须能在已发送文字中找到依据；常见中文否定/停用/过敏语境保守过滤。机器校验不等于理解全部医学语义，患者须核对医嘱。
- 本功能不额外保存原始模型全文或外发文本副本；只保存必要候选、依据、同意摘要和来源版本。错误返回通用描述，邮件通道错误不保存原始异常；沿用现有健康数据持久化和访问控制。
- 用药每次最多91天，每日最多6个不重复HH:mm；单次总提醒最多500条。开始日期不早于今天，每个所选药物须至少产生一个未来时刻。复查提醒默认当天09:00，已过时则确认后安排一次；这只是通知时间。
- 药物提醒独立于随访计划，完成复查不会停用药物提醒。暂停/完成随访仅影响该计划对应复查事件。
- 发送前复核来源与计划；通知已开始发送后无法保证召回。现有SMTP发送与状态提交之间仍有重复发送窗口，不能承诺严格一次。
- 需运行现有 Celery worker/beat。ETA入队失败后由定时扫描补捞，不保证断网/服务停止期间准点。站内待确认建议不发送邮件、短信、系统推送或锁屏内容。
