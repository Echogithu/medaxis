# 健康档案链路与验收

日期：2026-10-02（Asia/Hong_Kong）。范围来自用户确认：来源、更新时间、无／未知／未填写、用药有效／停用；采用慢性病／特殊疾病分类，增加严重程度、确诊日期和备注。AI 画像后置。

## 可观察行为

| 项目 | 行为 |
|---|---|
| 过敏、疾病、用药栏目 | 明确选择有记录、明确无、未知或未填写；空数组默认未填写，删除最后一项不自动成为明确无 |
| 疾病记录 | 名称支持自填或常见疾病；分类为慢性病／特殊疾病；严重程度为未知／轻度／中度／重度；确诊日期可留空，不能晚于今天；备注最多 1000 字 |
| 用药记录 | 名称、剂量、频率、开始日期及有效／已停用；停用保留历史，不进入当前用药；标记只记录患者陈述，不自动调整处方或提醒 |
| 来源与时间 | 新增或修改记录由服务器标记患者自报和更新时间；未改记录保留原时间。旧记录显示历史记录、来源未记录，时间未记录 |
| 保存 | 失败保留页面草稿；并发修改返回冲突，不覆盖已保存版本；重新加载前提示复制草稿 |
| 问诊链路 | 已认证患者的当前档案进入初诊、续问、诊断工作流及诊后聊天；访客不读取注册患者档案；AI 画像不进入此档案上下文 |
| 就医准备 | 疾病和有效／停用用药分别加入准备包；来源和时间保留，摘要使用中文健康信息；档案变化使已有准备包过期，需要重新生成 |

严重程度、确诊日期和用药状态都是患者自报，不等于医护核验。只有停用记录时，系统不推断患者“明确无当前用药”。基础信息显示注册年龄，移除原先不能保存的出生日期输入。

## 接口与兼容

`GET/PATCH /api/v1/patient/profile` 沿用现有疾病字段 `chronic_diseases`，由每条 `category` 区分 `chronic/special`，保留旧慢病数据。用药状态为 `active/stopped`。

服务器返回 `revision`、人工档案 `updated_at`、`section_states` 和 `section_metadata`。新记录来源及时间由服务器维护，客户端不能伪造成医生来源。PATCH 使用 `expected_revision`：版本不符返回 409；已有新版本时旧客户端未提供修订号返回 428。未升级的旧档案版本为 0。

输入边界：疾病和用药各最多 20 条，过敏最多 50 条；列表用 `[]` 清空，不接受 `null`；状态和列表必须一致。姓名不能为空，身高体重延续现有整数契约。

## 验证入口

后端目录执行：

```powershell
.\.venv\Scripts\python.exe -m tests.profile_chain_isolated
```

该脚本使用本机已有 `pgvector/pgvector:pg17` 镜像，新建独立容器和随机端口；迁移和 pytest 仅操作 `medaxis_test_*`，浏览器仅操作 `medaxis_demo_e2e_*`。完成或失败均清理自己启动的服务与容器。测试密码和签名密钥每次随机生成，不写入项目配置。浏览器 Python 可通过 `PROFILE_BROWSER_PYTHON` 指定，要求已安装 Playwright 和 Edge。

验证包括旧数据迁移保留、空元数据降级、已有元数据降级保护；真实认证和 PostgreSQL API 保存／重读、账号隔离、版本冲突、两次并发首次保存；首轮与续问的模型调用参数以及诊后上下文；浏览器保存／刷新、500 草稿保留、409 冲突恢复、390px 布局和空名称校验。

前端目录执行：

```powershell
node --test tests/patientProfile.test.mjs
.\node_modules\.bin\tsc.cmd -p tsconfig.app.json --noEmit
```

人工验收见 [.claude/manual-test-health-profile-chain.md](../../.claude/manual-test-health-profile-chain.md)。自动化模型边界使用替身，只证明档案被传递，不证明真实模型采纳或临床质量。

## 上线与恢复边界

运行环境需先备份数据库，在计划窗口执行 `alembic upgrade head` 到 `d4e5f6a7b8c9`，再更新应用服务。本轮仅运行隔离验收，不迁移现有业务库，不重启已有服务。

新增的 `record_metadata` 列保存来源、时间、状态和修订。若已有非空元数据，迁移拒绝直接降级删除该列；需先导出并确认恢复方案。回退应用时应保留元数据列，并避免旧客户端继续写入。工作区回退只针对本轮修改，不覆盖其他未提交工作。

随访计划和用药提醒的完整闭环仍按[原审查](./HEALTH_FOLLOWUP_MEDICATION_REVIEW.md)单独处理。
