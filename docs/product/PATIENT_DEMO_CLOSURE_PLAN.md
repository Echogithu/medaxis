## 目标与本轮范围

目标是在隔离演示环境，用**全新注册的合成患者**走通：输入主诉 → 至少一次补问 → 生成辅助报告 → 自动保存到唯一病例 → 从报告进入科室导航及就医准备 → 核对并携带摘要 → 在**同一病例**记录患者自报的就诊结果 → 清缓存重登后恢复。各页面、操作和 API 都使用同一个 `case_id`；失败时不得显示虚假成功。

本轮明确采用“**科室导航**”作为可展示的患者侧能力：提供可理解的科室目录/就诊方向浏览入口，标注来源、适用范围和不确定性，用户自己选择下一步咨询方向。无现成审核来源时，目录可以仅含中性的演示科室名称、版本及“非具体医院科室表”标识；不要写症状适应范围或症状到科室的映射。现有 `department.recommendation` 不得仅凭 AI 诊断名或自由文本来源填值。若项目没有经过专业审核的科室映射和可核查来源，**不做个性化科室推荐成功路径**，保留“依据不足/人工咨询”状态，并把原 PRD `FR-11/VP-01` 中的个性化推荐标为未完成。演示环境必须显著标明合成样例/演示，不得让演示规则进入真实患者路径。

这轮只验收**患者侧展示闭环**。原 PRD 的 FR-04 平台内医生复核、医生签署、自动随访/用药任务、预约/HIS、公开分享、真实机构挂号和临床正确性不在本轮完成声明中。患者可以在原病例记录“本人自报就诊结果”；不能显示为医生已确认。上传/解析可作为加分演示，但不作为主线前置条件；若页面允许上传，失败状态仍须真实可见。

此范围是为了尽快交付可复现的作品展示。它**不是**对原 PRD 中医生复核及个性化科室推荐已经完成的重新定义。简历只能写实际通过验收的患者侧能力。

4. 在同病例保存患者自报就诊结果；刷新、清除本地状态并重新登录，验证病例、报告、准备版本及自报结果从服务端恢复。
5. 加反例：重复完成诊断、病例 A/B 切换时 B 请求失败或延迟、跨患者读取/写入、准备保存失败、报告含 `red_flags`。核对 UI 提示、服务端记录和对象 ID 一致；不得靠测试断言变弱、额外 skip 或全链路 mock 让门禁变绿。
6. 运行相关后端测试及全量回归、前端测试、TypeScript 检查和构建；记录**本轮**命令、exit code、关键输出。实际上传/解析、真实模型及医疗内容专业审核若未跑，明确列为未验证，不用局部自动化结果替代。
